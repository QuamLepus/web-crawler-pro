Lifecycle of one job

POST /api/v1/jobs/crawl → quota gate → scheduler
→ BFS inside the start domain, robots.txt honoured
→ per page: clean → dedupe → store
→ progress written to wcp:v1:job:{id}
→ on finish: data_sha256 stamped, webhook emitted

Because the digest is written to the job record, a finished crawl can be listed on the data exchange directly.
