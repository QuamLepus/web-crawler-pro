# Web Intelligence OS implementation status

This status describes the code in this repository. It is not a promise that the
full long-term product plan is already shipped.

| Area | Current status | Important limitation |
|---|---|---|
| Topic discovery, crawling, search, APIs, web console | Existing foundation | Existing project behavior; not re-certified by the incremental tests in this change. |
| Grounded `/ask` and citations | Implemented against existing tenant index | Extractive answer only; not an autonomous crawl or independently verified answer. |
| Topic-to-report research | Async discovery + crawl jobs produce verbatim, timestamped, hashed excerpts with per-claim citations | Not LLM synthesis, independent source verification, or calibrated confidence; needs Celery workers/Beat and discovery providers. |
| Provenance ledger and manifest | Implemented with tenant-keyed Redis storage; optional HMAC export | Caller supplies provenance; older data is not backfilled; HMAC is not a public-key signature. |
| Knowledge graph | Tenant-isolated Redis entity/relationship API, bounded graph listing, and console canvas explorer | Exact alias resolution only; no fuzzy/AI resolution or automated extraction. |
| Python SDK | Early installable package for ask, crawl/status, watch, research, and tenant workflow CRUD/schedules/runs/cancellation | Limited endpoint coverage outside these areas; release and compatibility policy remain early. |
| Research console page | Implemented as a UI over `/ask` | It is not a multi-stage autonomous research agent. |
| Web change monitoring | Scheduled URL watches, one-page crawl snapshots, content hashes, change history with bounded before/after excerpts, up to 20 tenant-scoped text snapshots per watch (5,000 characters each; 90-day retention), basic text-based price mentions, `web.changed` webhook event, and watch-only public-address DNS pinning with redirect checks and bounded response size | Snapshots are text-only, not raw HTML/assets; no semantic change classification or structured product matching. Direct watch fetches require worker egress to public hosts and do not use ambient HTTP proxy settings. Celery Beat and workers must run. |
| Data Studio | Authenticated own-index query explorer with bounded search preview/export, tenant-scoped saved queries and immutable result snapshots, plus full-corpus SQLite aggregates (source/host/language/snapshot/day; count and mean authority/quality/body length), filters, pagination, charts, and aggregate CSV | Full-corpus analysis returns aggregates rather than document rows (100 groups/page; offset capped at 5,000) and may scan SQLite; no arbitrary SQL or full-corpus materialization. Search-result snapshots cover at most 100 hits, expire after 90 days, and are capped per tenant/size. A 50k-row synthetic warm-cache baseline is recorded; production-scale analytics latency remains unverified. |
| Workflow builder | Tenant-scoped sequential and dependency-DAG crawl recipes with create/list/edit/delete/run/status APIs, console and SDK controls, Celery execution, DAG-aware per-step status/progress, robots checks, request-budget accounting, cooperative cancellation, recurring schedules, and 30-day run-history search/status/inclusive-date filters backed by tenant-scoped indexes and a documented synthetic benchmark. Definition changes and schedule ticks share a short Redis lock; deletion is blocked while runs are queued/running. | Crawl-only (up to 10 steps / 25 pages each); DAG nodes are serial, not parallel; failed nodes skip descendants while independent branches continue. No arbitrary code or conditional predicates. The console has a read-only SVG graph preview; editing DAG dependencies uses JSON rather than a visual graph editor. Existing tenants pay a one-time lazy filter-index backfill; schedules require Celery Beat plus workers; cancellation waits for the active crawl step to finish. |
| Agent marketplace | Not implemented | Existing dataset marketplace is separate. |
| Enterprise connectors, SSO, compliance | Early tenant-configured OIDC Authorization Code + PKCE SSO, encrypted client secrets, verified-domain JIT controls, and bounded SSO audit history | Requires Enterprise plan and operator-managed encryption/public-base secrets; same-host HTTPS OIDC endpoints and RS256 only. No SAML, SCIM, deprovisioning sync, IdP MFA enforcement, complete compliance audit, or SOC 2/ISO certification. Live IdP and multi-replica validation remain. See `docs/enterprise-sso.md`. |
| Billing | Stripe-backed checkout, usage and webhook application; opt-in real test-mode Checkout integration and a secret-gated Stripe CLI HTTP-delivery smoke | Requires a Stripe test key and recurring test Price; the CLI delivery uses a generated fixture event, not completion of the Checkout Session, and neither the API call nor CLI delivery can run here without credentials. See `docs/stripe-testing.md`. |
| Observability and tracing | API OpenTelemetry spans, Prometheus metrics, Sentry hooks, and Celery W3C trace-context propagation with producer/task spans | OTLP export requires the optional `requirements-otel.txt` exporter and a configured collector; no production sampling, collector availability, backpressure, or end-to-end staging validation yet. Span attributes intentionally exclude tenant IDs, URLs, task payloads, and exception messages. |
| Python dependency profiles | Separate API, worker, optional AI, browser, development, search-index, and OTLP profiles; PR CI loads each service-specific Docker target, reports its Docker virtual size, and archives per-image reports; post-publish CI pulls all four GHCR application images, reports and archives their virtual sizes, and smoke-tests core Compose services including the dashboard, workers, Beat, and backing services | Profiles use version ranges, not a lockfile; reported size is the uncompressed Docker virtual size (not compressed registry transfer size). Compose smoke validates core-service readiness (MinIO only when Quay credentials are configured) but does not run the external-crawl CLI or test application integration with every backend. |
| Performance measurement | Reproducible synthetic own-index query benchmark and a small sandbox baseline are recorded | No production-scale, concurrent/API/browser, reranking, LCP/CLS, or cloud-cost benchmarks; targets remain unverified. |
| TypeScript SDK + MCP server | Early packages expose ask, research, crawl, watch, workflow control, and Studio snapshot operations; CI builds/tests both and checks package tarballs; MCP stdio protocol smoke tests cover initialize/list/call/error paths | Not published to npm; live API integration, complete endpoint coverage, and a stable compatibility/release policy remain. |

The implemented endpoints are tenant authenticated and tested with fakeredis.
Production deployments must configure Redis and protect
`WCP_PROVENANCE_SIGNING_KEY` using their secret-management system. The signing
key is intentionally optional: manifest export returns `503` if it is absent.
